# 킷 조립 규약

킷은 SDK로서 공개 유스케이스와 타입을 제공하고, 호스트 앱은 승인된 연결·저장·작업 실행을 조립한다. 내부 의존 방향과 역할은 [SDK 헥사고날 설계](architecture.md)를 따른다. 공통 실행 엔진이나 전체 호스트 기능을 받는 KitHost는 두지 않는다. marketplace가 첫 구현이며 다른 킷과 공유되는 타입이 확인되기 전에는 공통 contracts 패키지를 배포하지 않는다.

모든 킷은 [공개 유스케이스와 mock 규약](mock-contract.md)에 따라 실제/mock의 동일 입력 포트와 공개 반환 모델 주입을 제공한다. 앱은 조립 지점에서 구현을 선택한다.

## 공개 진입점과 호환성

패키지 메타데이터의 버전과 exports가 배포 계약의 정본이다. 각 킷은 README에서 지원 런타임, 설정·자격증명 요구, 부수효과, 호스트 의무, 검증 범위를 설명한다. 패키지 내부 경로나 다른 저장소의 소스 경로를 소비자가 import하지 않는다. GitHub 저장소는 공개이며 npm 패키지의 `private: true`를 유지해 registry에 공개 배포하지 않는다.

첫 marketplace 패키지는 Node 22와 Deno 2.9.6에서 산출물의 타입·실행을 검증한다. 이는 별도 Supabase 배포·Edge 자원 한도·판매자 계정 권한을 검증했다는 뜻이 아니다. 런타임 호환성은 실제 통과한 CI·예제 범위로 표시한다. `0.x`에서도 공개 입력·오류·커서·결과 의미를 바꾸면 변경 내역과 소비자 전환 방법을 함께 기록한다. 이전 커서 형식을 지원하지 않으면 조용히 초기화하지 않고 오류로 반환한다.

## 부수효과와 자격증명

import와 factory 생성은 자격증명 조회·네트워크·DB 변경·타이머·작업 예약을 실행하지 않는다. 명시적인 읽기 호출에서만 해당 연결의 자격증명과 외부 통신을 사용한다. 호스트는 사용자·조직 권한을 검사하고 한 연결에 한정된 자격증명 resolver를 제공한다. SDK는 resolver가 반환하는 계정이 호스트가 승인한 연결과 일치하는지 대신 인증하지 않는다.

서버용 진입점은 브라우저 번들에 포함하지 않는다. 웹은 `import type`과 타입 전용 진입점을 사용한다. SDK는 환경변수를 읽거나 키·토큰을 영속 보관하지 않으며, 오류에 원문 응답이나 원본 exception을 붙이지 않는다. 실제 개인정보를 수집하거나 저장할 범위와 수명은 호스트가 결정한다.

## 외부 통신과 동시 실행

마켓 호스트와 endpoint는 SDK가 고정한다. 요청은 redirect를 따르지 않고, 기본 제한시간은 15초이며 1~120000ms 범위에서 설정할 수 있다. 응답 본문은 최대 8MiB로 제한한다. 실패한 읽기를 빈 결과로 바꾸지 않는다. `MarketplaceError.code`로 인증·권한·제한·입력·응답 계약·전송·취소를 구분한다. 제공자가 반환한 오류 메시지를 그대로 노출하지 않는다.

`beforeRequest`는 각 실제 요청 전에 호출된다. bucket과 operation은 제공자 계약을 아는 SDK가 정하고 호스트가 분산 제한을 실행한다. 기본 동작은 즉시 실행이며 SDK가 여러 worker의 호출량·잠금을 보장하지 않는다. 토큰 캐시·동시 발급 합치기는 한 클라이언트 인스턴스의 최적화다. 다른 프로세스나 인스턴스의 갱신·제한은 호스트가 조정한다. 제공자 제한값은 운영 계약으로 확인해야 한다.

## 수집과 저장

SDK는 한 페이지의 정규화된 결과·다음 커서·조회 범위·관측 시각을 반환한다. 호스트는 결과와 커서를 한 트랜잭션으로 저장한 뒤 다음 페이지를 읽는다. 상세 조회가 일부 실패하면 페이지 전체가 실패하며 다음 커서가 확정되지 않는다. 커서가 없다는 것은 선택한 조회 범위의 순회를 마쳤다는 뜻이며 주문 전체·클레임 전체의 완전 수집을 보장하지 않는다.

커서는 연결·조회조건·형식 버전을 검증하는 불투명한 진행 값이다. 암호화나 인증 수단이 아니므로 내용을 수정하지 말고 같은 소유 범위에서 보관한다. 연결 소유 확인은 항상 호스트가 수행한다. 스캔 재시작·겹치는 기간의 중복 제거·재대사는 호스트 책임이다. 소스의 변경 피드와 상태별 스캔을 같은 updatedSince 계약으로 취급하지 않는다.

현재 킷은 읽기만 제공한다. 원격 쓰기·재시도·결과 불명·부분 성공 계약과 영속 작업 원장은 후속 구현 범위다. 읽기 호출의 request 식별값만으로 외부 쓰기의 멱등성을 추정하지 않는다.
